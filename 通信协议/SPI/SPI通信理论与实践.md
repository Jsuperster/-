# SPI 通信理论与实践

> 面向初学者，讨论常见的四线、单数据线宽度、同步串行 SPI。SPI 没有一份能统一所有器件事务格式的通用规范：命令、地址、dummy 周期、片选要求与最高频率必须以具体器件数据手册为准。

## 1. SPI 是什么，谁负责什么

SPI（Serial Peripheral Interface）通过时钟同步数据，常用于 MCU 与 Flash、ADC、DAC、显示屏及传感器之间的短距离通信。通常由一个主机产生时钟并选择从机。现在部分手册使用 controller/target 命名，原理相同。

常见四根信号为：

| 信号 | 方向（相对主机） | 作用 |
|---|---|---|
| SCK / SCLK | 输出 | 串行时钟 |
| MOSI / COPI | 输出 | 主机发给从机的数据 |
| MISO / CIPO | 输入 | 从机发给主机的数据 |
| CS / SS / NSS | 通常输出 | 片选，常见低有效 |

此外还需供电及适当的公共参考地。主机的 MOSI 接从机数据输入，MISO 接从机数据输出，不要只看引脚缩写相同就盲接。有些器件使用 SDI/SDO，必须确认命名是从哪个器件视角定义。

主机外设负责按配置产生时钟、移位收发及管理 FIFO；驱动负责 CS 和事务组织；从机的数据手册规定寄存器、命令、地址、忙状态与读写协议。SPI 本身通常不提供地址仲裁、接收 ACK、自动重发或统一 CRC。软件 API 返回成功不等于从机认可命令，更不等于 Flash 擦写已经完成。

## 2. 电气层与多从机连接

常见 SPI 是 CMOS 推挽单端接口，不像 I²C 那样默认开漏，也不应机械地给每条线加上拉。逻辑电平必须兼容：3.3 V 输出不能默认接到不耐 3.3 V 的 1.8 V 输入；从机输出的高电平也必须达到主机 VIH 要求。使用电平转换器时，应检查方向、传播延迟、带宽和上电状态，通用自动双向转换器不一定适合高速 SPI。

多个从机通常共享 SCK、MOSI、MISO，各自使用独立 CS。未选中的从机应按手册要求将 MISO 置高阻，否则多个推挽输出会争用。还要注意 CS 释放后 MISO 进入高阻所需的延迟；切换从机时不能让两个器件同时驱动总线。若器件不满足共享要求，应加缓冲、隔离或使用独立总线。

CS 通常低有效，但极性、上电默认状态和脉冲要求都不是绝对统一的。为防止启动时误选，常见设计会对 CS 使用合适的上拉；是否需要及阻值如何选择，应结合漏电、启动时序和板级设计。

三线半双工、双线/四线数据、QSPI/OSPI、菊花链等是扩展或特殊连接，不应直接套用本文四线全双工的事务假设。

## 3. 四种模式：先定义边沿，再记表格

**CPOL 决定 SCK 空闲电平：**CPOL=0 时空闲为低，CPOL=1 时空闲为高。

**前导沿（leading edge）**是时钟离开空闲电平的第一个边沿；**后随沿（trailing edge）**是返回空闲电平的第二个边沿。因此 CPOL=0 的前导沿是上升沿，CPOL=1 的前导沿是下降沿。

**CPHA 决定采样发生在一对边沿中的哪一个：**

- CPHA=0：在前导沿采样，在后随沿更新下一位；第一位必须在首个前导沿之前已有效并满足建立时间。
- CPHA=1：在前导沿推出/更新数据，在后随沿采样；首个前导沿用于推出第一位，不是采样第一位。

| 模式 | CPOL | CPHA | 空闲电平 | 采样沿 | 数据推出/更新沿 |
|---|---:|---:|---|---|---|
| Mode 0 | 0 | 0 | 低 | 上升沿（前导沿） | 下降沿（后随沿）；首位提前准备 |
| Mode 1 | 0 | 1 | 低 | 下降沿（后随沿） | 上升沿（前导沿） |
| Mode 2 | 1 | 0 | 高 | 下降沿（前导沿） | 上升沿（后随沿）；首位提前准备 |
| Mode 3 | 1 | 1 | 高 | 上升沿（后随沿） | 下降沿（前导沿） |

这里的“更新”表示允许发送端改变输出位，接收端在另一边沿采样。实际输出存在传播延迟，还必须满足接收端建立与保持时间；不能把边沿画在同一竖线上就认为时序天然成立。器件手册可能写“第一边沿/第二边沿”或使用不同相位命名，最终应以波形和 AC 时序表对应关系为准。

### 3.1 文字时序：以 Mode 0、MSB first、发送 0xA5 为例

0xA5 的二进制为 `1010 0101`：

```text
SCK 原来为低，CS 拉低，等待片选建立时间。
MOSI 提前放好 bit7=1。
第 1 个上升沿：从机采样 bit7；主机同时采样 MISO 的 bit7。
第 1 个下降沿：双方准备各自发送方向的 bit6。
第 2 个上升沿：双方采样 bit6。
……
第 8 个上升沿：双方采样 bit0。
第 8 个下降沿：完成最后一个时钟周期，SCK 回到低电平。
确认移位发送结束，满足 CS 保持时间后，CS 拉高。
```

Mode 1 则在第 1 个上升沿推出 bit7、第 1 个下降沿采样 bit7，直到第 8 个下降沿采样 bit0。Mode 2/3 的电平与边沿方向相反。位序 MSB first/LSB first 是另一个独立配置，不由 CPOL 或 CPHA 决定。

## 4. 全双工与 dummy 读：读数据也要发送

普通四线 SPI 在每个数据位时钟同时推进 MOSI 和 MISO，因此发送一个 8 位字节的同时，主机也接收一个 8 位字节。某个方向的数据可以没有业务意义，但电气移位仍发生。主机读数据必须提供时钟，常通过发送 dummy 字节（占位数据）来产生时钟。

### 4.1 一个明确假设的寄存器读取算例

假设某器件手册规定：8 位读命令 `0x80 | 寄存器地址`，随后立即输出一个寄存器字节；地址 0x12，寄存器值 0x3C，则一次事务为：

```text
CS：  拉低 ───────────────────────── 拉高
MOSI：       0x92          0x00（占位）
MISO：       无效/忽略     0x3C（有效）
SCK：        8 个周期      8 个周期
```

主机总共发送两个字节并接收两个字节，第二个接收字节才是结果。这里的 0x00 仅为例子；从机可能要求 0xFF 或其他值。读命令格式也是例子，不能套给所有传感器。

**dummy 发送字节与器件规定的 dummy 等待周期不是同一概念。**前者是主机为了产生接收时钟而放到 MOSI 的占位数据；后者是器件在命令/地址之后规定的无效等待时钟。例如某存储器要求 8 个 dummy 周期，这段 MISO 不能当有效数据，之后还需继续提供时钟才能读出数据。等待周期未必是整字节，需确认控制器是否支持。

## 5. CS 与连续事务：字节边界不等于命令边界

很多从机把一次 CS 有效区间视为一个完整事务：命令 → 地址 → dummy 周期 → 数据。CS 中途拉高可能使从机终止或重置命令状态机。因此不能默认连续调用几次单字节发送 API，就等效于一次完整事务。

- 需要连续 CS 时，可使用软件 GPIO 控制 CS，并以一次或多段传输完成整个命令。
- 使用硬件 NSS 时，核对它是否每个字、每个 FIFO 块或每次 DMA 自动产生脉冲，不能只看到“NSS 已开启”就认为符合协议。
- 有些器件允许 CS 有效期间暂停时钟，有些限制最大字节间隔；连续 CS 不代表允许无限暂停。
- 某些 ADC 或 DAC 恰恰要求固定宽度 CS 脉冲，或者用 CS/LDAC 边沿锁存数据；不能一律追求拉低越久越好。
- 多任务共享总线时，从设置模式/速率到 CS 释放应作为受保护的事务，避免任务交错破坏命令。

Flash 页编程的串行移位结束后，器件通常还需内部编程时间。应按照手册轮询 busy/WIP 位或等待就绪信号，而不是看到主机发送完成就读写下一条不被允许的命令。

## 6. 频率、建立保持时间与预算算例

SCK 频率不仅受主机分频器限制，也受从机最高频率、时钟占空比、CS 时序、电压温度、连线和电平转换器影响。数据手册中的“最高 50 MHz”往往带有供电电压、负载和工作模式条件。

### 6.1 MISO 半周期预算

假设从机在一个边沿更新 MISO，主机在下一个相反边沿采样，时钟占空比近似 50%。用一组假设参数估算：

- SCK 从主机传播到从机：2 ns。
- 从机 SCK 到 MISO 有效的最大延迟：18 ns。
- MISO 从从机传播回主机：2 ns。
- 主机输入建立时间要求：5 ns。
- 为抖动、偏斜和其他不确定性预留：3 ns。

总预算为 `2 + 18 + 2 + 5 + 3 = 30 ns`。应满足：

```text
T_SCK / 2 ≥ 30 ns
因此 f_SCK ≤ 1 / 60 ns ≈ 16.7 MHz
```

若外设内核时钟为 80 MHz、分频只可取 2、4、8、16……，20 MHz 不满足此示例预算，可先选 10 MHz 并验证。实际设计应依据主机采样参考点与器件时序定义计算，不能重复或漏算已有参数包含的延迟。

这只是 **MISO 建立时间的一条约束**，还须检查 MOSI 路径、最小延迟对应的保持时间、SCK 高低电平最短时间、CPHA=0 首位与 CS 建立时间及最后一位的 CS 保持时间。实际占空比不是 50% 时，应使用对应最短边沿间隔，而非直接取半周期。

### 6.2 有效吞吐率

在 10 MHz 下，读取事务包含 1 字节命令、3 字节地址、1 字节 dummy 等待和 16 字节有效数据，总共 21 字节、168 个时钟。纯移位时间为 16.8 μs，有效数据吞吐率约为：

```text
16 B / 16.8 μs ≈ 0.952 MB/s（十进制）
```

实际还要加 CS 建立/保持、高电平间隔、驱动调度与器件等待。10 MHz 不等于每秒 10 MB；单线宽度每个时钟每个方向只传一位。全双工可以同时传两个方向，但不能据此把单方向有效吞吐率翻倍。

## 7. 通用驱动配置流程

1. **读从机协议**：确定电压、片选极性、模式、位序、字宽、频率、命令格式、dummy 周期及事务边界。
2. **检查硬件**：引脚复用、供电、公共地、电平转换、MISO 高阻条件与 CS 默认状态。
3. **配置时钟和 GPIO**：核算外设内核频率；在从机未选中时设置正确的 SCK 空闲电平，避免切换模式造成误时钟。
4. **初始化 SPI 外设**：选择主机、全双工、CPOL/CPHA、8/16 位数据宽度、位序、分频和 NSS 策略；处理芯片要求的模式故障条件。
5. **清理旧状态**：按参考手册清除溢出和错误，处理残留 RX 数据，准备接收缓冲区。清标志的读写顺序因芯片而异。
6. **从低速轮询验证**：先读已知器件 ID 或固定寄存器，使用逻辑分析仪确认 CS、模式、字节顺序和有效数据位置。
7. **再启用中断或 DMA**：明确传输长度、FIFO 阈值、数据对齐和缓冲区生命周期。在真正全双工模式中，即使只关心发送，也应处理产生的 RX 数据，避免溢出。
8. **加入超时和恢复**：出错时安全终止 CS、停止相关 DMA/外设、按手册清状态并释放总线锁，防止永久阻塞。

16 位数据宽度不意味着线上字节序自动符合从机需求；还需核对内存端序、外设装载顺序和协议字段的高低字节顺序。

### 7.1 DMA 完成为什么不等于发送完

TX DMA 完成通常仅表示最后一个数据单元已经从内存搬到外设 FIFO/数据寄存器。它可能仍在 FIFO 中，或者正在移位寄存器中逐位发出。如果立即拉高 CS、关闭时钟或禁用 SPI，会截断最后一个字节。

稳妥做法是依据所用控制器的定义确认**串行传输完成**，例如检查 EOT/TC 或按手册等待发送 FIFO 空且 BSY 清零，再满足 CS 保持时间后释放 CS。不能跨芯片照搬某个状态位，也不能认为所有“Tx complete”驱动回调都是同一种完成语义。

全双工 DMA 通常需先准备接收通路再启动发送以产生时钟；具体使能顺序以外设手册为准。即使 RX DMA 已收齐，也要确认最后时钟边沿和片选保持要求已完成。带数据缓存的 MCU 还需处理 DMA 缓冲区的可访问内存、对齐与缓存一致性：发送前按平台要求 clean，接收前后按要求维护缓存，并避免误影响共享缓存行。

## 8. 信号完整性与测量

SPI 的问题往往来自**边沿太快**，而不仅是 SCK 频率高。低频时钟仍可能有亚纳秒上升沿，使长飞线表现为传输线，产生振铃、过冲或多次跨越输入阈值。

- 缩短 SCK 与数据走线，提供连续参考地，减少长支线和大面积回路。
- 按需降低 GPIO 驱动速度；在驱动端附近评估适当串联阻尼电阻。主机驱动的 SCK/MOSI 与从机驱动的 MISO，其“源端”不同。
- 不要随意给单端 SPI 加 CAN 式 120 Ω 终端；阻值与方式应根据驱动能力、阻抗和波形设计。
- 排查连接器、电平转换器、探头电容及多个从机输入负载。
- 逻辑分析仪用于看协议，示波器用于看幅度、边沿、振铃和时序裕量。逻辑解码正常不代表模拟波形合格。
- 使用短接地弹簧等低电感测量方式；探头本身也可能改变原本边缘可用的信号。

SPI 一般适合板级短距离连接。跨长电缆时应认真评估差分扩展、隔离或改用更适合的链路，不能只靠降低频率和加粗线来保证可靠性。

## 9. 排错表

| 现象 | 可能原因 | 检查步骤 |
|---|---|---|
| 总是读到 0xFF | MISO 浮空、从机未选中、输出尚未有效 | 查 CS、供电、引脚方向、命令和 dummy 周期 |
| 总是读到 0x00 | 短路、错误命令、从机未启动 | 示波器观察 MISO，检查复位与上电等待 |
| 数据整体错一位 | CPHA 错、首位未建立、CS 时序不满足 | 对照首个沿采样关系与时序图，不只改模式试运气 |
| 仅最后一字节错 | DMA 后过早释放 CS 或关闭外设 | 查真正 EOT/BSY 语义和 CS 保持时间 |
| 低速正常高速失败 | 建立时间不足、振铃、转换器延迟 | 重算频率预算并测量模拟波形 |
| 单独可用，共享后失败 | MISO 争用、CS 交错、模式切换错误 | 检查高阻释放时间，给完整事务加锁 |
| DMA 数据偶发旧值 | 缓存未维护、缓冲区失效、长度单位错 | 查内存区域、缓存行、DMA 字宽及 API 长度单位 |
| 命令后返回值偏移 | 忽略命令阶段 RX 或漏算 dummy | 按时钟数标出每个字节真正含义 |

## 10. 带答案自测

1. **Mode 2 的首个时钟沿是什么，是否采样？**空闲高，首个沿是下降沿；CPHA=0，所以它采样第一位，第一位必须提前有效。
2. **Mode 3 的首个下降沿是否采样？**不是。它推出第一位，随后上升沿采样。
3. **为什么读取 1 字节还需要发送占位字节？**主机需要产生 8 个时钟才能移入 8 位数据；MOSI 内容按从机协议选择。
4. **读命令占 1 字节、随后需要 8 个 dummy 周期，再读 2 字节，总共多少时钟？**8+8+16=32 个时钟；有效数据不含命令和 dummy 阶段。
5. **TX DMA 完成能立即拉高 CS 吗？**不能默认如此；必须确认最后数据已移出、最后时钟完成并满足 CS 保持时间。
6. **上述频率预算中，20 MHz 是否满足 30 ns 半周期要求？**不满足，20 MHz 半周期仅 25 ns。
7. **SPI 读回预期值一次，是否足以证明模式正确？**不够。部分图样或低速可能掩盖错误，应测试多种图样并直接核对边沿和建立保持时间。

## 11. 手册阅读建议与权威资料名称

推荐先看从机时序图，再配置主机外设；随后查看 AC 特性和芯片勘误。将“首位何时有效、哪一沿采样、CS 何时结束”画在纸上，通常比只记 Mode 数字更可靠。

以下仅列可查阅资料名称与关键词，不虚构统一 SPI 标准编号或引用页码：

- **Motorola SPI Block Guide / Freescale SPI Block Guide**：CPOL、CPHA、master/slave transfer、shift/sample edge；注意它描述相应外设实现，不统一所有从机命令。
- **所用 MCU 的 Reference Manual，SPI 章节**：clock source、baud-rate prescaler、NSS pulse、FIFO、BSY、EOT、DMA、overrun；并查该型号 Errata Sheet。
- **所用 MCU/处理器的数据手册，SPI AC Characteristics**：input setup/hold、clock duty cycle、output delay、voltage/temperature conditions。
- **Winbond W25Q 系列 SPI NOR Flash 数据手册（以实际完整型号为准）**：Read Data、Fast Read、dummy clocks、Chip Select timing、WIP、Page Program。
- **Analog Devices ADXL345 Data Sheet**：SPI read/write、multiple-byte transfer、3-wire/4-wire SPI；仅用作具体器件协议阅读示例。
- **所用 ADC/DAC/传感器及电平转换器数据手册**：serial interface timing、CS setup/hold、MISO high impedance、propagation delay。

阅读时特别确认：参数是典型值还是最坏保证值，时序以哪个边沿为参考，单位是 bit、byte、frame 还是 clock，以及该结论适用于哪个供电、速度等级和芯片修订版本。
