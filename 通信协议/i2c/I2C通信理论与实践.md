# I2C 通信理论与实践

> 面向电子嵌入式初学者。学习目标：理解两根线如何完成寻址、应答和寄存器访问，能够估算上拉电阻并排查总线异常。下文是通用流程，不是可直接套用到任何芯片的驱动代码。

## 1. I2C 是什么

I2C（Inter-Integrated Circuit，也写作 I²C）是一种同步串行总线，使用 SCL 时钟线和 SDA 数据线。控制器（传统名称“主机”）发起事务、产生时钟；目标器件（传统名称“从机”）按地址响应。本文使用“控制器/目标器件”，阅读旧手册时应注意名称对应。

多个目标器件可共享两根线，但地址不能冲突；重复地址可通过地址引脚、地址配置、复用器或独立总线解决。I2C 支持多控制器，但硬件、驱动和仲裁策略必须支持，不能把两个独立单控制器程序直接接到一起就认为可靠。

常见模式包括标准模式 100 kbit/s、快速模式 400 kbit/s、快速模式增强型 1 Mbit/s。高速模式有额外进入流程和电气要求，不是简单把分频器调快。系统速率必须满足总线上所有相关器件与电气条件，且 SCL 频率不等于有效载荷速率。

## 2. 开漏、上拉与电气安全

常规双向 I2C 的 SDA、SCL 使用开漏/开集电极方式：参与者可以拉低线路，也可以释放线路，**不能用普通推挽输出强行驱高**。当所有器件释放时，上拉电阻使线路变高；任何一个器件拉低，线路就为低。这是 ACK、仲裁和时钟拉伸能够工作的基础。

```text
             Vpullup                 Vpullup
                |                       |
               Rp                      Rp
                |                       |
控制器 SDA -----+------ 目标器件 SDA    |
控制器 SCL ---------------------------+------ 目标器件 SCL
各器件 GND -------- 共同参考地 ---------------- GND
```

上拉电压必须同时满足每个引脚的输入高阈值、工作电压和最大额定值；3.3 V 器件不一定容忍 5 V。电压域不同应选择支持双向开漏的适当转换方案，并考虑器件掉电时反向供电。不要认为“都叫 I2C 就一定能直接相连”。

总线电容包含引脚、走线、线缆、连接器、转换器以及测量探头电容。I2C 更适合板内或较短距离连接；是否可延长取决于电容、干扰、时序和缓冲方案，不能只按线长下结论。模块板可能已经带上拉，多块板并联后总电阻会变小。

## 3. 上拉电阻 RC 估算与上下界

释放线路后，电压近似按 RC 曲线上升：`V(t)=VDD×(1−e^(−t/RC))`。以 30%～70% 电平区间定义上升时间，在简单集中参数模型下：

```text
tr ≈ 0.8473 × Rp × Cb
Rp(max) ≈ tr(max) / (0.8473 × Cb)
Rp(min) ≈ (Vpullup − VOL(max)) / IOL
```

其中 `Cb` 是总线总电容，`VOL(max)` 是所允许的低电平电压，`IOL` 是器件能保证该低电平时的灌电流。应按总线中最弱的拉低能力及适用标准选取，不能把绝对最大电流当作可长期使用的保证值。

**计算例子：**3.3 V 总线工作在快速模式，假设 `Cb=100 pF`，采用该模式常见的 `tr(max)=300 ns`；器件保证在 3 mA 灌电流下 `VOL≤0.4 V`。

- `Rp(max)=300 ns/(0.8473×100 pF)≈3.54 kΩ`。
- `Rp(min)=(3.3−0.4)/3 mA≈967 Ω`。
- 取 2.2 kΩ，估算 `tr≈186 ns`，在上述简化条件下位于允许范围内。
- 若电容增至 200 pF，同样电阻得到约 373 ns，不满足本例 300 ns 上限。

电阻太大，上升慢，容易导致高电平有效时间不足；电阻太小，灌电流和低电平功耗增加，还可能拉不低。两个 4.7 kΩ 并联相当于 2.35 kΩ。实际应计入阻容容差、漏电、输入阈值和波形裕量。若上下界没有交集，应降低电容、调整速率或采用合适的缓冲方案，而不是任意减小电阻。

## 4. 起始、停止、数据与 ACK/NACK

通常情况下，SCL 为高时 SDA 应保持稳定；SDA 在 SCL 低时改变。两个特殊事件例外：

- **START（S）**：SCL 为高时，SDA 从高变低。
- **STOP（P）**：SCL 为高时，SDA 从低变高。
- **Repeated START（Sr，重复起始）**：没有先发 STOP，再次产生 START，用于保持一次组合事务的连续性。

```text
事件示意（H=高，L=低）
START：SCL 保持 H，SDA H → L
STOP ：SCL 保持 H，SDA L → H
普通数据位：SCL=L 时准备 SDA；SCL=H 时接收方采样

一个字节：  D7 D6 D5 D4 D3 D2 D1 D0 | ACK/NACK
SCL 脉冲：   1  2  3  4  5  6  7  8 |    9
位序：       最高位先发             | 接收方应答
```

每个字节之后都有第 9 个时钟。此时发送方释放 SDA，接收方拉低表示 ACK，不拉低表示 NACK。

ACK 的发出者取决于方向：控制器写数据时，由目标器件应答；控制器读数据时，由控制器应答。连续读中，控制器通常对还想继续读取的字节发 ACK，对最后一个字节发 NACK，然后产生 STOP。**最后一字节 NACK 是正常结束通知，不一定是错误。**

地址或写数据阶段的 NACK 可能表示地址错误、器件不在线、器件忙、命令不接受或电气时序异常，必须结合器件协议判断。ACK 也不一定代表业务操作已完成，例如 EEPROM 接收写命令后还可能需要内部写周期。

## 5. 7 位地址与 API 差异

常见 7 位地址是器件身份，不包含读写位。线上紧随 START 的地址字节是：

```text
位：   7  6  5  4  3  2  1 | 0
内容： A6 A5 A4 A3 A2 A1 A0 | R/W
地址字节 = (7位地址 << 1) | R/W
R/W=0：写；R/W=1：读
```

若 7 位地址为 `0x48`，线上写地址字节为 `0x90`，读地址字节为 `0x91`。某些资料把后两者称作“8 位地址”，容易误解。

**驱动 API 没有统一约定：**有的传入 `0x48` 并由驱动左移；有的要求传入左移后的 `0x90` 再由硬件或驱动设置方向；还有接口接收完整地址字节。必须查函数参数说明和实现，不能凭函数名猜测。逻辑分析仪也可能显示 7 位地址而不是原始地址字节，应核对解码设置。

7 位编码有 128 种组合，但包含保留地址，并非全部都可任意分配；I2C 还有 10 位寻址，不能简单套用上述单字节编码。

## 6. 重复起始：读取寄存器实例

假设一个虚构传感器使用 7 位地址 `0x48`，寄存器指针为 8 位，从寄存器 `0x10` 连续读取两个字节：

```text
S | 0x90 | A | 0x10 | A | Sr | 0x91 | A | DATA0 | A | DATA1 | N | P
    控制器发  控制器发        控制器发    目标发       目标发
       目标ACK  目标ACK          目标ACK    控制器ACK    控制器NACK
```

步骤解释：先以写方向发送寄存器指针，再不释放事务地发重复起始，改成读方向读取数据。重复起始本身不是一个数据字节，也不额外带一个 ACK 位。有些器件允许两次独立事务之间插入 STOP，有些要求重复起始；应以目标器件的寄存器访问规范为准。

若返回 `0x12, 0x34`，并且器件约定高字节在前，则原始值为 `(0x12<<8)|0x34=0x1234=4660`。这不代表温度就是 4660 ℃；符号位、有效位宽、量程和比例系数必须继续查手册。寄存器地址也可能是 16 位，有的器件没有寄存器指针模型。

忽略起止条件时间及拉伸，上述事务有 5 个 9 时钟单元，即 `45` 个 SCL 周期。在 400 kHz 下约需 `45/400000=112.5 μs`，两字节有效载荷的理想速率约为 `17.8 kbyte/s`，远小于把 400 kbit/s 直接除以 8 得到的结果。

## 7. 驱动配置与时钟拉伸

1. 检查电源、地、地址引脚、上拉电压和阻值，确认所有器件支持目标速率。
2. 配置外设时钟和引脚复用，按器件要求使用开漏模式。内部弱上拉通常不能直接替代经过计算的外部上拉。
3. 根据外设时钟、总线升降时间、数字/模拟滤波设置计算时序参数；不要照搬不同主频芯片的时序常量。
4. 核对 API 地址格式、寄存器地址宽度、字节序和组合事务能力。
5. 实现带超时的事务，分别处理地址 NACK、数据 NACK、仲裁丢失、总线错误及超时。
6. 先测试单字节寄存器，再测试重复起始、连续读写和忙状态。用逻辑分析仪对照每个字节的应答来源。
7. 多任务共享总线时，用锁或队列保护**整个组合事务**，而不仅保护单个字节发送。DMA/中断完成是否意味着 STOP 已完成，应查具体驱动语义。

**时钟拉伸**指目标器件在需要等待时继续拉低 SCL。控制器释放 SCL 后必须确认线上确实已升高，不能只按软件延时认为高电平已经出现。是否允许拉伸、在哪些阶段拉伸、控制器硬件是否支持，都要查模式和器件说明。

基础 I2C 不能直接套用 SMBus 的所有超时规则。工程上仍应设置适合具体设备的超时，避免永久阻塞；超时过短也会把合法的拉伸或忙状态误判为故障。多控制器环境发生仲裁丢失时，应释放总线并按策略重试，而不是立即发送恢复脉冲干扰获胜者。

## 8. 总线卡死后的谨慎恢复

先判断 SDA、SCL 的真实电平，以及是否有其他控制器正在正常通信。上电复位时序、半途复位、掉电反灌、短路和器件状态机停在半个字节都可能导致总线忙。

在**已确认没有其他控制器活动，且器件允许此恢复方式**时，若 SCL 可升高而 SDA 被拉低，可参考 I2C 总线清除机制：

1. 先结束或禁用本地事务，按芯片要求暂时把引脚切换为开漏 GPIO，避免外设继续驱动。
2. 释放 SDA；对 SCL 产生至多 9 个受控时钟脉冲。每次释放 SCL 后确认它实际变高，并满足时序，同时观察 SDA 是否释放。
3. 若 SDA 释放，可在合法电平条件下生成 STOP：先在 SCL 低时拉低 SDA，再释放 SCL并等待高电平，最后释放 SDA。不能用推挽强拉高。
4. 确认两线空闲后，重新初始化控制器、缓冲状态和目标器件协议状态，再有限次重试。

若 SCL 一直被拉低，控制器无法强行产生有效时钟；应先排除合法拉伸、短路和未供电器件，必要时按器件规定复位或受控断电。9 个脉冲不是万能修复，失败后应停止盲目重试。恢复过程中可能改变寄存器指针或事务状态，对 EEPROM 写入、执行命令等操作还要评估重复执行和数据一致性风险。

## 9. 常见故障排查表

| 现象 | 常见原因 | 排查方法 |
| --- | --- | --- |
| 地址始终 NACK | 地址左移错误、地址脚状态错误、设备未就绪 | 对照 API 与线上地址字节，检查供电及启动时间 |
| 100 kHz 正常，400 kHz 失败 | 上升过慢、时序参数不符、设备不支持 | 测量 30%～70% 上升时间，重算上拉及高低电平时间 |
| SDA 或 SCL 长期为低 | 短路、拉伸、掉电钳位、事务中断 | 先看真实电平和供电，再按允许流程恢复 |
| 读出固定错值 | 寄存器指针宽度、端序或重复起始错误 | 按手册逐字节核对，区分原始值和物理量 |
| 连续读取最后报 NACK | 把正常结束误判为失败 | 确认 NACK 是否由控制器发给最后一个读字节 |
| 加模块后低电平抬高 | 多组上拉并联使灌电流超限 | 计算等效阻值，核对最弱器件的 VOL/IOL |
| 偶发超时 | 任务竞争、合法拉伸、噪声或仲裁 | 锁住完整事务，记录错误阶段并观察模拟波形 |

地址扫描不是完全无副作用的万能探测。某些器件对特定命令或读写序列敏感，也可能在忙时 NACK；应先查看设备手册并避免随意访问保留地址。

## 10. 带答案自测

1. **为何不能把 SCL 设置成推挽并强制拉高？** 可能与拉伸或其他器件的拉低动作冲突，破坏线与逻辑并产生过大电流。
2. **7 位地址 0x3C 的线上读地址字节是多少？** `(0x3C<<1)|1=0x79`；API 是否需要这个值仍取决于接口约定。
3. **最后一个读字节的 NACK 由谁产生？** 控制器，表示不再继续接收；随后通常产生 STOP。
4. **4.7 kΩ、100 pF 的估算上升时间是多少？** 约 `398 ns`，不满足本例快速模式 300 ns 上限。
5. **重复起始读寄存器为何先写一次？** 写入的是寄存器指针，而非一定写入寄存器内容；随后切换读方向。
6. **SCL 被持续拉低时，发九个恢复脉冲一定有效吗？** 不一定，甚至无法产生实际脉冲。需先定位拉低者，不能强拉高或无限恢复。

## 11. 应查阅的权威资料与关键词

本文未联网引用具体版本；实际设计应查阅：

- NXP《UM10204 I2C-bus specification and user manual》：START、STOP、ACK、clock stretching、arbitration、bus clear、rise time、reserved addresses。
- TI《I2C Bus Pullup Resistor Calculation》（SLVA689）：pull-up resistor、bus capacitance、VOL、IOL。
- MCU 厂商《参考手册》《数据手册》《勘误手册》及驱动 API 文档：I2C timing、filter、address format、repeated START、BUSY、timeout。
- 实际传感器、EEPROM、转换器及总线缓冲器数据手册：register map、address pins、power sequencing、write cycle、level translation。
- 若实现 SMBus：适用版本的《System Management Bus Specification》，重点核对其超时、电气及协议要求，勿与基础 I2C 混用。

**技术自查要点：**开漏不强拉高；上拉同时满足上升时间和灌电流限制；7 位地址与线上字节分开；最后一字节 NACK 属正常结束；重复起始按器件规定；总线恢复必须确认安全条件。
