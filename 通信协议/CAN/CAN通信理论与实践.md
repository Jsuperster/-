# CAN 通信理论与实践

> 面向初学者，以经典高速 CAN（Classical CAN，ISO 11898-2 高速物理层）为主。文中的电压、时钟和寄存器参数是解释原理的示例，不替代所用控制器、收发器与整车/设备网络规范。

## 1. 先分清三个层次

CAN 是一种允许多个节点共享总线、通过报文进行通信的串行网络。它具有逐位仲裁、差错检测和故障隔离机制，常见于汽车、工业控制和机器人。

一个节点通常由以下部分组成：

- **CAN 控制器**：通常位于 MCU 内，负责帧格式、仲裁、CRC、ACK、位时序、错误计数及收发 FIFO。
- **CAN 收发器**：将控制器的 TXD/RXD 逻辑信号转换为 CAN_H/CAN_L 差分电气信号。收发器不负责解释报文内容；待机、静默和故障引脚需要正确配置。
- **应用层协议**：规定 ID 含义、数据编码、单位、字节序、发送周期、超时及请求应答，例如 CANopen、J1939 或自定义协议。

因此，“MCU 带 CAN”不代表可以把 MCU 引脚直接接到 CAN_H/CAN_L；“总线有 ACK”也不代表应用程序已经处理命令。

## 2. 电气层：显性、隐性与接线

经典高速 CAN 通常使用双绞线 CAN_H、CAN_L。接收端主要判断两根线的电压差，同时必须满足收发器的共模输入范围。非隔离设备通常还需要合适的参考地连接；差分通信并不意味着可忽略地电位差。长距离、强干扰或异地供电场景应评估隔离与浪涌保护。

- **显性位 dominant：逻辑 0**。典型 5 V 高速收发器下，CAN_H 约 3.5 V、CAN_L 约 1.5 V，形成约 2 V 差分。
- **隐性位 recessive：逻辑 1**。典型情况下两线均在约 2.5 V 附近，差分接近 0。

这些不是所有器件的保证值；3.3 V 器件、低功耗状态及故障状态可能不同，应看数据手册。多个节点同时发送时，只要一个节点发送显性，正常总线就呈显性，这构成仲裁的物理基础。

### 2.1 拓扑与终端

优先采用**线形主干，两端终端，节点通过短支线接入**。不要默认星形、长支线或任意树形可以在目标速率下可靠工作。传播延迟、反射、连接器和支线长度共同限制通信距离与速率，不能只背一张“速率—距离表”。

主干的两个物理末端通常各接一个 120 Ω 终端电阻，匹配约 120 Ω 的线缆特性阻抗；中间节点通常不再加终端。分裂终端一般由两个约 60 Ω 电阻串联跨接两线，中点按设计接电容等网络，不是给每个节点都装两个 120 Ω。

**断电测阻前提：**整条被测网络的所有节点均已断电，排除 USB、调试器等反向供电，等待电容放电，确认没有带电电压，再在 CAN_H 与 CAN_L 之间测量。网络必须仍连接着预期的两个终端；主动终端、可切换终端、保护网络及器件漏电可能改变结果。

- 约 60 Ω：常见于两个 120 Ω 并联，只说明静态终端数量看似合理，不证明布线与信号质量合格。
- 约 120 Ω：可能少了一个终端，或中间断线使另一端不可见。
- 约 40 Ω：可能存在三个 120 Ω 终端。
- 接近 0 Ω 或很大：分别检查短路、开路或终端未接入。

不得在带电网络上直接使用电阻档作此判断。

## 3. 报文、ID 与工作过程

经典 CAN 数据帧的数据区为 0～8 字节。标准帧使用 11 位 ID，扩展帧使用 29 位 ID。**ID 是报文标识及仲裁优先级的一部分，不是 CAN 机制规定的节点地址。**应用协议可以在 ID 中编码源地址或目的地址，但那是上层约定。同一报文可被多个节点接收，接收过滤器仅决定本控制器向软件保留哪些帧。

数据帧可以概括为：

```text
总线空闲 → SOF → 仲裁字段 → 控制字段 → 数据 → CRC → ACK → EOF → 帧间隔
             ID 等          长度信息    0～8 B
```

经典 CAN 支持远程帧，用于请求相应 ID 的数据帧；它没有数据区，实际使用取决于应用协议。不要把远程帧当成所有网络都必须支持的应用功能。

发送前控制器等待合法的总线访问时机，然后发送帧并持续监测总线。接收节点检查位填充、格式、CRC 等条件。经典 CAN 从 SOF 到 CRC 序列的规定范围内采用位填充：连续五个相同位后插入一个相反位，接收端移除它。因而实际帧长与数据有关，不能仅以 8 字节除以波特率估计总线占用。

### 3.1 仲裁文字时序

假设两个标准数据帧同时开始发送，ID 分别为 0x120 和 0x123：

```text
ID 最高有效位先发送；相同前缀期间双方继续。
遇到首个不同位：A 发 0（显性），B 发 1（隐性）。
总线被 A 拉成显性；B 发 1 却读到 0，判定仲裁失败。
B 停止争用并转为接收；A 的帧不被破坏，继续发送。
B 等待后续机会重试，而不是产生错误帧。
```

同种帧格式下，数值较小的 ID 通常优先级更高；精确仲裁还涉及 RTR、SRR、IDE 等位。当标准帧与扩展帧的前 11 位 ID 相同，标准帧优先。不要直接把一个 11 位 ID 和一个 29 位 ID 当普通整数比较优先级。

不同节点不应同时用相同 ID 发送不同内容：它们可能同时通过仲裁，随后在数据区发生位冲突，引起错误和重发。高优先级流量过多还可能使低优先级报文长期等待，应用设计必须控制负载和最坏等待时间。

### 3.2 ACK 到底证明什么

发送节点在 ACK 槽发送隐性；正常参与通信且正确接收帧的接收节点可以发送显性确认。ACK 是总线上的合并结果，发送者不能知道由谁确认。

**ACK 只说明至少有其他节点在协议层正确接收，不保证目标节点存在、过滤器接受、FIFO 未溢出、软件已读取或业务已执行。**正常接收器的 ACK 通常不以应用过滤器是否接收为条件。静默/监听模式一般不发送 ACK，单节点正常发送测试因此可能出现 ACK 错误并自动重发。需要业务可靠性时，另设计序号、应用应答、超时与重复命令处理机制。

## 4. 位时序、采样点与 SJW

一个标称位时间通常分为：

```text
| Sync_Seg = 1 tq | Prop_Seg | Phase_Seg1 | Phase_Seg2 |
                                         ↑ 采样点
```

`tq` 为时间量子。某些控制器把传播段与第一相位段合并为 TSEG1 或 BS1，把第二相位段称为 TSEG2 或 BS2。设真实分频系数为 BRP：

```text
tq = BRP / CAN内核时钟
每位量子数 N = 1 + TSEG1 + TSEG2
位速率 = CAN内核时钟 / (BRP × N)
采样点百分比 = (1 + TSEG1) / N × 100%
```

注意，寄存器可能保存“实际值减一”，时钟也可能来自独立外设时钟而非 CPU 主频。

### 4.1 500 kbit/s 配置算例

假设 CAN 内核时钟 40 MHz，实际 BRP = 5，取 TSEG1 = 13、TSEG2 = 2：

- tq = 5 / 40 MHz = 125 ns。
- 每位共 1 + 13 + 2 = 16 tq，位时间 2 μs。
- 位速率 = 500 kbit/s。
- 采样点在 14 / 16 = 87.5%，即位开始后 1.75 μs。
- 可考虑 SJW = 2 tq，即最多 250 ns 的单次重同步调整，但必须满足具体控制器的段长限制。

**SJW（同步跳转宽度）**限制一次重同步允许调整的最大量，不是额外附加的时间段，也不直接改变标称位速率。控制器利用符合规则的边沿校正时钟相位误差；SJW、采样点、晶振容差、收发器延迟及线缆往返传播延迟必须联合评估。

87.5% 是常见选择，不是万能标准。高速、长线或不同振荡器精度可能需要其他方案；不能只要求两端“都是 500 kbit/s”而忽略采样点与时钟误差。

## 5. 通用驱动配置流程

1. **确认硬件**：电源、引脚复用、收发器型号、TXD/RXD、EN/STB 控制、终端及接地。不要把 TXD 接 CAN_H。
2. **确认时钟树**：计算 CAN 内核实际频率，核对时钟源稳定性和精度。
3. **进入初始化模式**：按控制器要求停止总线活动后设置位时序、SJW 与正常/回环/静默模式。
4. **配置过滤器**：明确标准/扩展 ID、掩码含义、远程帧策略以及接收 FIFO 分配。初次调试可在受控网络适当放宽过滤器。
5. **配置收发资源**：FIFO、邮箱、消息 RAM、发送优先规则、自动重发策略及溢出行为。
6. **使能事件处理**：接收、发送完成、错误告警、错误被动和 bus-off 中断；中断中尽快取数据并排队，避免长时间阻塞。
7. **启动控制器与收发器**：确保实际进入正常工作态。先做内部回环验证软件，再用至少两个正常节点进行外部通信验证。
8. **加入应用监控**：时间戳、接收超时、丢帧统计、总线负载、错误计数、bus-off 次数及恢复日志。

发送 API 返回“入队成功”通常不代表已发到线上；应检查发送完成事件及其仲裁丢失、取消、错误等状态。具体含义由驱动 API 定义。

## 6. 错误隔离与 bus-off 恢复

CAN 控制器维护发送错误计数 TEC 和接收错误计数 REC。正常状态为 error-active；当 TEC 或 REC 达到 128 时进入 error-passive；当 TEC 超过 255 时进入 bus-off。计数增减有多种例外，不能简化为“每错一次加一”。

bus-off 节点不再正常驱动总线，避免故障节点持续破坏网络。**恢复不是清一个标志就一定完成。**经典 CAN 的总线恢复判据涉及检测 128 次、每次 11 个连续隐性位；控制器是否自动开始该过程、是否要求软件请求、状态与计数如何复位，应查参考手册。

推荐策略：记录错误原因和状态 → 停止无意义的发送堆积 → 排查短路、缺 ACK、位时序和收发器状态 → 按手册请求或等待恢复 → 确认恢复完成 → 受控恢复业务。反复 bus-off 应限流、退避并告警，不能无限重初始化掩盖物理故障。业务恢复还需重新确认对端状态，避免旧命令积压后突然执行。

## 7. 排错表

| 现象 | 常见原因 | 推荐检查 |
|---|---|---|
| 完全没有差分波形 | 引脚复用错误、收发器待机、未真正发送 | 查 TXD、STB/EN、控制器模式和发送队列 |
| 持续 ACK 错误 | 单节点、对端静默、速率错误、断线 | 接入正常第二节点，查看实际时钟和线缆 |
| 有 ACK 但应用没数据 | 其他节点应答、过滤错误、FIFO 溢出 | 核查 ID 类型、过滤掩码、接收中断与软件队列 |
| 短线可用、长线失败 | 反射、支线过长、传播预算不足 | 查两端终端与采样点，用差分测量观察波形 |
| 偶发错误随电机启动增加 | 共模干扰、接地或电源问题 | 检查供电瞬态、隔离、屏蔽与布线 |
| bus-off 反复出现 | 接线/时序故障未消除 | 保存 TEC/REC 与错误状态，先修根因再恢复 |
| 某些报文延迟很大 | 总线过载或低优先级被压制 | 统计负载、ID 优先级和最坏响应时间 |

示波器测量须遵守探头接地安全，优先使用适合的差分探头；不要将接地夹误夹到 CAN_H 或 CAN_L 上。

## 8. CAN FD 与经典 CAN 的边界

CAN FD 支持最多 64 字节数据，并可通过 BRS 在数据阶段切换到更高速率；不是所有 FD 帧都会切换速率。超过 8 字节时，DLC 与字节数不是简单的一一数值对应。FD 的帧格式、CRC、位填充规则等也与经典 CAN 不同，且 FD 不支持远程帧。

支持 FD 的控制器通常可配置发送经典帧；但普通经典 CAN 节点不能默认与正在发送 FD 帧的节点兼容共存，它可能将 FD 帧视为错误。数据阶段速率、收发器带宽、传播延迟补偿及网络拓扑需单独设计，不能把经典 CAN 的配置算例直接套给 FD 数据相位。

## 9. 带答案自测

1. **0x100 是节点 256 的地址吗？**不是。CAN 定义的是报文 ID；是否编码地址由应用协议决定。
2. **发送获得 ACK，能否证明电机执行了动作？**不能。需要目标应用发送具有明确语义的应答，必要时确认实际状态。
3. **40 MHz、BRP=5、总计 16 tq，位速率多少？**500 kbit/s；若 TSEG1=13，采样点为 87.5%。
4. **仲裁输了算通信错误吗？**不算。这是正常的无破坏总线访问过程，节点等待重试。
5. **断电测出 60 Ω，能否认定网络完全正常？**不能。还需确认无反向供电及测量条件，并检查动态信号、拓扑和时序。
6. **增大 SJW 可以任意补救错误波特率吗？**不能。它只在硬件规则允许的范围内校正相位偏差。
7. **bus-off 后反复软件复位是可靠修复吗？**不是。先修根因，再依控制器手册与应用安全策略恢复。

## 10. 手册阅读建议与权威资料名称

推荐阅读顺序：板卡原理图 → MCU 时钟树与 CAN 控制器章节 → 收发器数据手册 → CAN 协议规范 → 应用层协议。使用具体型号及对应芯片修订版本的文档，并同时查看勘误表。

以下仅列可查阅资料名称与关键词，不声称本文逐条引用了某一版的具体条款：

- **ISO 11898-1，Road vehicles — Controller area network (CAN) — Data link layer and physical coding sublayer**：Classical CAN、arbitration、bit timing、error confinement、bus-off recovery；注意不同版本的覆盖范围。
- **ISO 11898-2，Road vehicles — Controller area network (CAN) — High-speed physical medium attachment (PMA) sublayer**：termination、common-mode range、propagation delay。
- **Bosch CAN Specification Version 2.0**：standard/extended frame、ACK、bit stuffing、fault confinement。
- **所用 MCU 参考手册的 CAN/bxCAN/FDCAN 章节及勘误表**：kernel clock、prescaler encoding、filter、FIFO overrun、automatic retransmission、bus-off。
- **所用高速 CAN 收发器数据手册，例如 TI TCAN1042 系列、NXP TJA1042 系列**：operating modes、bus pins、logic voltage、loop delay、ESD；各子型号能力不可互相代替。
- 使用对应应用层时，再查 **CiA 301（CANopen）**或 **SAE J1939 系列**：对象字典、报文定义、地址管理、超时与网络管理。
